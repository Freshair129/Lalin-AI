# Windows installed remix runtime

Full sidecar builds include librosa and its runtime. The packaged sidecar does not embed torch or Demucs and does not embed GPL remix plugins. For installed remix and preview, provision a separate Python environment containing compatible torch and Demucs, then set `GMUSIC_DEMUCS_PYTHON` to the absolute path of its `python.exe` before launching the desktop application. Model weights must also be available to Demucs. Missing or invalid configuration is reported by the preview job. With this external runtime, `auto` currently selects CPU; explicitly selecting CUDA passes that choice to Demucs. Other optional effects remain subject to their existing plugin limitations.

This is a workstation configuration, not a bundled Demucs installer or clean-machine acceptance. A full build installs `requirements-full.txt`; lite builds retain their previous dependency exclusions. The installed GUI and end-to-end workflow must be validated independently of the sidecar `/health` check. For CUDA, the GPU queue applies the configured remix VRAM threshold to preview and render; its probe runs in the external environment, waits if VRAM is insufficient and fails the job if the probe cannot run. The child resets the inherited Windows DLL search path before importing its audio modules, though interpreter startup still precedes the reset; compatibility across other installed Python environments remains unverified.

On 2026-11-01, local unsigned NSIS installer SHA-256 `87F5871B1A72AE08352FD0C1E64C6C71384AE3CF1DD39FA34A8178DB483E0EF9` installed with exit 0. The installed sidecar hash was `D517A5C91F4F687BC10CBC64C2248FE5E80DA291013E30DBF970EEDDB353B634`, matching the built sidecar. With a separately configured Demucs environment, CUDA, and a 512 MiB remix admission threshold, the installed GUI opened an isolated API-created test project referencing uploaded licensed fixtures, created a drift preview, and played both global-only and warp audio. Editing only that test preview's manifest expiry induced a server-expiry response: the GUI hid stale controls and offered regeneration. Regeneration created a new preview, and GUI acceptance completed a render with `warp_applied=true`. This controlled-expiry test does not establish clean-machine installation, sound quality, signed updater behavior, or support for arbitrary external Python environments.
